# Blobscape

Blobscape (blobscape.dev): lessons, a sandbox and small experiments with Gaussian splats. One Vite
multi-page React app, one Vercel project, served from the root. See README for the why behind the choices.

## Commands
- `npm run dev`, `npm run build` (hosting:check + tsc, vite build, then `scripts/prerender.ts`), `npm run preview` (production headers)
- `npm test` — unit tests for the pixel pipeline and the Gaussian fitter (node --test, no GPU)
- `npm run check` before merging: `npm test`, the build, then `verify --changed` (only the browser checks the changed files reach, by imports; a file half the checks import runs the `core` set, `--wide` for all). All three print a line or two when they pass and each failure once; the rest is in `verify-shots/` (`tests.txt`, `build.txt`, `report.txt`): read the summary, open a report only for a failure it names (`npm run test:loud`, `verify --loud` for everything). A failed browser check runs once more alone; one that then passes is `flaky`, not a failure. `.github/workflows/check.yml` runs the unit tests and the build on every PR; the browser checks are not reliable on GitHub's runners yet (docs/testing.md), so run `npm run check` yourself. Full `npm run build && npm run verify` (every check, three at a time) for build, hosting or harness changes, or when asked. Real Chromium against dist with vercel.json headers, plus axe; screenshots in verify-shots/. Checks live in `scripts/verify/checks/` with the source files they cover; a new page or experiment needs one. See docs/testing.md.
- Releases: add a line under `## [Unreleased]` in CHANGELOG.md for anything a visitor would notice. `npm run release -- x.y.z` makes the release PR; merging it to main makes `.github/workflows/release.yml` tag it, make the GitHub release (sessions can't push tags) and publish `@blobscape/engine` at the same version once its manifest isn't `private` (npm org `blobscape`; by npm trusted publishing, no stored token). Merge a release PR only when Matt says go. See docs/releasing.md.

## Load-bearing
- Vite `base: '/'`, `outDir: 'dist'`, Vercel `trailingSlash: true` (every page is a folder with an index.html). `hosting:check` enforces it.
- Blobscape's pages are paths (`/`, `/lessons/`, `/lessons/<id>/`, `/sandbox/`, `/experiments/`, `/experiments/creature/`, `/experiments/four-ways/`, `/engine/`, `/engine/rigged-splats/`, `/contact/`), parsed in `routes.ts`. `scripts/prerender.ts` writes each one's HTML (title, description, canonical, og, JSON-LD, readable content) from the built `dist/index.html`, plus 404.html, sitemap.xml, robots.txt. Every page is rendered by the app itself through Vite's SSR loader (`src/blobscape/ssr.tsx`, `<App route>`), so the first paint is the page and doesn't jump (verify's `site` check compares the heading's place before and after the app starts). Pages that draw no WebGL at first (`HYDRATED`: home, lessons, experiments, engine, spec, docs, contact, 404) are marked `data-ssr` and hydrated by `main.tsx`; on those, anything that reads the browser (storage, `document`) must read it in an effect, not while rendering, or the hydrated page keeps the prerendered value. Lessons and the WebGL experiments read the address and saved progress as they start, so `main.tsx` draws them afresh over the prerendered page (never hydrate them); on the server they see a plain address (`renderPage` stands in a `location`), so a page must render without `window`: guard `matchMedia` with `typeof window`, and keep everything else that needs the browser in effects. Both fonts are preloaded, and `theme.css` has per-weight metric-matched fallbacks (`Figtree Fallback`, `Fredoka Fallback`) so text doesn't reflow when they arrive. A new page needs a case in `routes.ts`, `meta.ts` and `prerender.ts`.
- `useLinkNavigation` turns plain clicks on links to Blobscape pages into in-app navigation; tools and other sites load normally. Old `#/…` links are rewritten to paths on load.
- CSP needs `'wasm-unsafe-eval'` and `worker-src blob:` (Spark decodes in WASM, sorts in a blob worker).
- Every experiment lives under `/experiments/` (old `/creature/` and `/tools/*` addresses redirect there). Add a new tool: `experiments/<name>/index.html` + `src/<name>/`, an input in vite.config.ts, an entry first in `EXPERIMENTS` (src/blobscape/site.ts: front page, menu, the Experiments page; newest first) with its `tags` (kinds from `TAGS`, the Experiments page's one-at-a-time filter, kept as `?tag=`; at least one each, tested) and its `published` and `updated` days (the footer's `NEWEST_EXPERIMENTS` and the Experiments page's order come from `published`; bump `updated` only for a change a visitor would see, not site-wide work; the dates show on the cards, on each experiment's crumb line via `Crumbs`, in its JSON-LD and as its sitemap lastmod) and the sitemap list in prerender.ts. Every page renders `SiteHeader` (src/shared) first, puts its content in `<main id="main">` for the skip link, and ends with `Footer` (src/shared).
- Brand: colors are hex tokens in `src/shared/theme.css` (light default, dark three times: system, forced, `.case`; keep them in step). Blob coral `#f2553a` (`blob`) is for the logo and big shapes, never small text; `accent` is the text-safe coral. Headings `font-display` (Fredoka 600), text Figtree. Logo shapes in `src/shared/logoPaths.ts`; don't recolor, stretch or add effects. The theme choice is stored as `blobscape-theme`.
  Tabs, sliders, chips and toggles live in `src/shared/ui.tsx`; reuse them so every experiment shares the same hover and cursor states.
- Every experiment page uses one layout, `Workbench` (src/shared/Workbench.tsx): the preview on the left (two thirds, 4:3, sticky; on phones on top at 45% of the screen, in `svh` so it does not change height as the address bar hides), one options panel on the right split into tabs (each tab's box is `TAB_SECTIONS`: every direct child is a section with a rule above it, so wrap a multi-part section in one div), an optional `footer` under the tabs, and a full screen button on the preview (it fills the window where the browser has no element full screen, as on iPhones; `fullScreenAt` moves it off a game's HUD). Anything that does not act on the preview goes in a card below. While a view waits it shows `LoadingMark` (src/shared/BlobLoader.tsx): three blobs moved only by `transform` on their own elements, so the compositor keeps them going while a build holds the main thread; the page's sr-only status line says what it waits for. The tab names are Matt's (project memory `experiment-layout`); verify checks them and that the columns are the same size on every page, and its `tabClick` opens a control's tab before clicking it.

## Splat to Sprite
- three.js + Spark (`@sparkjsdev/spark`). Live view = scene SparkRenderer; sprite = a second, offline SparkRenderer with a render target, sorted for the sprite camera (`engine.ts`).
- Read the target with sync `readRenderTargetPixels`; Spark's async `readTarget()` stalled in headless Chromium.
- The viewport only renders when invalidated or while Spark is mid-sort; Spark picks up a finished sort only on the next render, so don't stop on `framesLeft` alone.
- Sheet JSON mirrors Tinkerkit's `SpriteSheet` (tinkerkit packages/format/src/spritesheet.ts, format 71); rows down/left/right/up.
- Commit as `mtblck <105079242+mtblck@users.noreply.github.com>` or Vercel blocks the deploy.

## Fit a Picture
- `fit.ts` is the whole trainer (render, loss, hand-derived backward pass, Adam, prune, densify) on typed arrays; it runs in `trainer.worker.ts` and in Node tests. Change a gradient → `npm test` (finite-difference check).
- Blobs add up (no sorting): pixel = Σ opacity·color·falloff. Params are log scales, angle, and sigmoid color/opacity.
- The worker posts a frame ~30×/s with the display image, new losses and events; the page keeps losses in a ref buffer, not state.

## Splat engine (prototype, `src/splat-engine/`, test page `/engine-lab/`)
- The engine lab is deliberately unlisted (noindex, no hub card): it's a test bench, not an experiment.
- `Skeleton.place` is where an actor stands; poses (`offset`, `rotation`, `reset()`) never touch it.
- Our own renderer for animated splats, on three.js's WebGPURenderer (TSL). `SplatWorld` holds every blob of every actor. WebGPU, per frame: deform compute (bones → world center + covariance), project compute (→ screen center + ellipse axes, writes sort keys and histogram), `DepthSort` prefix + scatter (`sort.ts`, one counting sort over the whole scene), then a lean instanced draw. Projection/shading follow three's `GaussianSplat` (MIT). A still object is one bone.
- The sort must give the same order for the same view: the scatter's threads race within a depth bin, so `DepthSort`'s settle pass orders each small bin by index, and `setView` keeps bins a fixed width anchored in depth. ## Brush and Ink (`/experiments/brush-and-ink/`, `src/blobscape/BrushInk.tsx`, `src/splat-core/marks.ts`; issue #235)
- Marks: `SplatWorld.setMarks(look)` / `Stage.setMarks` (kept across actors) draws every blob as a brush mark or ink stroke instead of a soft dot, in the splat fragment (`markOf` in engine.ts) on both backends. A mark is a function of the pixel's place on its own blob (σ units along the screen ellipse's long and short axes) and the blob's seed (`splatSeed`, the `lodRank` hash) and of nothing on the screen, so marks turn with the view and never swim. `markAt` in `splat-core/marks.ts` (pure, tested) is the CPU twin: change one, change both. The ellipse's axes can flip sign frame to frame, so every mark must look the same after a half turn (hatching uses `|v|`; a test holds it). Gouache and oil are opaque strokes with streaks (oil adds ridges that catch light); ink and wash is a pale wash with a pen stroke along each blob; hatching draws more lines where the color is darker. Ink and paper colors are part of the look, and the page puts the paper color behind the canvas (`brushLooks.ts`: `LOOKS`, `PAPERS`, `GROUND`).
- Marks are drawn by depth, not by paint order (Matt saw the stripes on the windmill's sails jump as each came round, 2026-11-18): sorted far to near by their centers, the blobs of one flat thing on a grid all change places at the same moment as it turns in the view, and opaque marks show it. So while marks are on the material writes depth, a mark is all there or not (`MARK_CUT`), and `placeQuad` puts each corner at the blob's own depth there (`tilt` from `projectSplat`, kept in the `splatC` buffer on WebGPU; `depthSlope` in marks.ts is the CPU twin, change both) plus a lift by the blob's seed (`MARK_LIFT`), so blobs in one plane tie and the seed says which is on top. The project pass and the draw (with clean cuts) now each bind 8 storage buffers, the most a phone allows. `MarkLook.soft` keeps the old far-to-near laying with soft edges: a scan's thick, overlapping blobs shred into patches by depth, so the scanned mug and Scan Studio use it.
- Outlines (Matt asked, 2026-11-18: an ink drawing with no contours made no sense): `Stage.setOutline(pen)` draws through `splat-engine/inkLines.ts` `InkLines` when not in pixel mode. The frame is drawn three times with one sort (picture, `SplatDepth`, the map of parts) and one pass inks a pixel a pen's width from where the picture's own cover ends, something is clearly nearer (`LINE_DEPTH`), or a lower-numbered part meets another at the same depth (thinner, `LINE_PART`). Weight is `lineWeight` in marks.ts (the CPU twin of `lineWeightNode`; change both): heavier round dark things, swelling along the line, lifting off round light ones; the line wobbles by smooth noise over the screen, so it is the one thing here that does not turn with the view. Ink and wash is a pale wash (`WASH_LEAST` to `WASH_MOST` by darkness) with pen strokes only in shade (`SHADE_FROM`), since the outlines now do the drawing. On for ink and hatching by default (`?outline=0|1`), offered for every look; Scan Studio turns them on with its two pen looks.

## Sand, Snow and Goo (`/experiments/sand-snow-goo/`, `src/blobscape/SandSnowGoo.tsx`, `src/blobscape/flow/`, `src/splat-engine/mpm.ts`, `src/splat-engine/solids.ts`; issue #162, reworked 2026-11-18)
- Matt's rework: one material at a time and a test, or All three as three lanes; never two materials in one box (on a shared grid they stick as one). The page opens on what its first tab shows (sand, pouring onto a block). Tabs Material, Test, View (my names, not Matt's yet).
- `mpm.ts` (pure, tested) is a 3D MLS-MPM on the CPU: a [0, 1] box on a `cells`³ grid, quadratic B-splines, APIC, `dt` of `STEP_PER_CELL / cells` (3 ms at 24: stiffness, cell size and `dt` are tied, so a stiffer material or a finer grid needs a shorter step). All three are Hencky elasticity with their own way of giving, set by `Mpm.set(knobs)` (`Knobs`, two settings each). Sand: Drucker-Prager (`friction`; `slopeOf` measures the heap), its cone moved into pulling by `damp`. Snow: the same cone with a hold (`stick`) times each particle's bond (`Jp`), which weakens wherever it gives down to `SNOW_CRUMB` (that is what makes clumps; without the crumb share a column either stood whole or fell whole), and a cap on squeezing that rises as it packs (`packed`, `pack`). Goo: volume is elastic and never swells (a swelling stream blew up), shape past `hold`'s yield drains at `thick`'s rate. The first goo clamped every singular value, so it lost 85% of its volume instead of flowing: keep the volume test. Each particle keeps the stress from its last decomposition (`tau`), so a step needs one `svd3` (unrolled; it is a third of the time). Particles stay where all 27 nodes are on the grid, so the loops need no bounds checks. `floorGrip` is the floor's friction (goo's is low, or a thin puddle can't spread on a grid this coarse).
- `solids.ts` (pure, tested, in the package): a `Solid` is a voxel.ts `Shape`, fixed (block, steps, bowl) or a rigid body with weight (`density`). On the grid (`Mpm.meet`) material moving into a fixed solid stops and rubs; a body and the grid points moving into it come away at one speed along the way out, solved for all of them at once (a 6×6, `solve6`), because an explicit kick shook a light body under a heavy heap; the sideways rub is shared by weight for the same reason. A particle the grid let in is put back on the surface and stopped (a lone particle is too few points to be stopped by the grid, and kept speeding up), and a body is kicked back by as much. A body meets the floor, walls and fixed solids on points of its own surface (`corners` for a cube; a ball passes `round` and uses the exact point, or it rocks on its points). It sleeps when still and wakes every `NAP` to see whether what held it has gone.
- `flow/box.ts` (pure, tested) is one box: `Setup` (material, test, ground, thing, size, weight, detail), the spout (a layer each time the stream has fallen a particle's spacing, until one `SPOUT.amount`), the pile and the thing let go after `DROP.after`, the round column, the grounds' shapes, `DETAILS` (cells and capacity per detail) and `frame()`: positions, a `shade` per particle (the grid's mass thins toward the surface, so its gradient is the way out, lit by the same sun as voxel.ts) and `tone` (snow's packing, drawn darker so a print shows). `flow/flow.worker.ts` runs one box as close to real time as the device allows and posts frames ~30 times a second, each with the `id` of its `start` so the page drops a late frame of the last box; All three is three workers.
- `flow/view.ts` builds one actor in the simulation's units (root bone scaled by `SIZE`): per lane a bone with the ground and tray rim cut by `buildVoxels`, a bone each for ball, cube and rock built at `THING_BUILT` and scaled by bone size (the two not falling are size 0), then `capacity` particle blobs a lane on the root (hidden ones clear and tiny, so the count never changes); the page `refresh`es each new frame, as Shape Shifter does. Changing anything on the Test tab, the material or the detail starts the box again; the Material tab's sliders act on the running box. A short tap pokes (`CreatureStage.rayAt`, the nearest particle along the ray in any lane, else that lane's floor). Under reduced motion each box is run 5 s at once and shown paused. Verify drives `window.__flow` with `?offscreen=1` (`?material=&test=&ground=&thing=&detail=`): `pause`, then `run(seconds)` for a set time, `lanes()` and `thing()`.

## Pixel Diorama (`/experiments/pixel-diorama/`, `src/blobscape/PixelDiorama.tsx`, `src/blobscape/diorama/scene.ts`)
- Pixel-art scenes from splats, in three parts. `splat-engine/voxel.ts` (pure, tested) cuts shapes given as distance functions into one grid shared by every part; each surface cell is one solid disc lying on the surface, on one bone, with sun, ambient and cast shadows baked into its color. Lit colors stop at `LIT_MAX`; only `glow` parts go brighter, and pixel mode's `GLOW_FROM` sits just above it, so a lamp glows and a white wall doesn't. Keep the two in step.
- Pixel mode is `CreatureStage.setPixels(look, size)`: `splat-engine/pixelPass.ts` draws the scene small into a target, then one full-screen pass does alpha cut, glow, edge lines inside the scene (`edges`: the darker side of an OKLab jump over `EDGE_JUMP`), OKLab palette + Bayer dither, a silhouette outline and an optional `sky` (a top-to-bottom gradient on empty pixels, dithered into the palette; leave it out for sprites; its optional third value, a scene's `skyReach`, is how far down the blend runs before it is all the bottom color), scaled up by a whole number of device pixels. `pixelArt` in `splat-core/pixel.ts` is its CPU twin (change one, change both; verify compares them on WebGPU and WebGL). `stage.pixelFrames()` reads the small frame and the art back. The pass always draws into its `art` target (kept in sRGB, so palette colors are stored exactly) and the screen gets a plain scaled copy. It keeps the art of the frame before as well: a look with `steady` (the page's Steady pixels switch, `STEADY`) lets a scene pixel keep its palette color unless another is clearly closer, which stops pixels between two colors flipping as lights flicker and the view swings. Only a pixel that is scene now can stick: sky and glow-only pixels never do (a pixel the scene has left would keep its color). `?steady=0` starts with it off. `CreatureStage.step` (the page's Motion choice: Smooth, 12 or 8 a second) holds frames: the pose only moves on every `step` seconds and nothing is drawn in between, which is what stops edges crawling while a view swings; `stage.time` is the held time. `pixelArt(f, look, before)` does the same given `pixelFrames().before`. Lines between parts (`PixelLook.parts`, with or without `edges`): the pass draws the blobs a second time into `ids` as a map of parts (`SplatWorld.parts`: every blob a hard disc in its part's flat color, from `Actor.partOf`, reusing the frame's sort), and a pixel beside another part whose color is too close for a color line takes a line when its part is the lower-numbered (by number, not lightness, so the line keeps its side as lights flicker). `pixelArt`'s fourth argument is that map (`pixelFrames().parts`). Lone-pixel cleanup (`PixelLook.tidy`, the page's Clean up lone pixels switch, on by default, `?tidy=0` starts it off; issue #114): a second pass over the art (`tidied`; `art` is that target when on, while `before` stays the uncleaned art, which is what steady pixels compare against) gives a scene pixel the color six or more of its eight neighbors share when none shares its own; with a map of parts, only a pixel among four or more of its own part, so specks and eyes stay. `tidyLone` is its CPU twin, which `pixelArt` runs last.
- Every scene also has a recorded loop (`public/loops/<id>.webp`, lossless, one pass at 12 fps, plus `<id>.png`, its first frame, shown under reduced motion), recorded from the build by `node --experimental-strip-types scripts/record-loops.mjs [out] [ids…]` (stepped with `stage.frame(t)`, so a loop joins up; about 10 minutes a scene here; also writes a 3× MP4 for posting). `diorama/Gallery.tsx` shows them under Pixel Diorama (a tile picks the scene) and on the engine page (`ENGINE_LOOPS`); `diorama/loops.ts` lists them apart from `scenes.ts` and `loops.test.ts` keeps the lists in step, so a new scene needs a recorded loop. Record a scene again after a change you'd see.
- Record the loop (Finish tab, for every visitor; Matt chose that over a hidden link or logins, 2026-11-17): the page pauses, steps one whole loop at `RECORD_FPS` with `stage.frame(t)` (the half second before the start first, for steady pixels), reads each `pixelFrames().art`, and saves either a lossless animated PNG at the art's own size (`splat-core/apng.ts`, our writer, tested; deflate through CompressionStream) or an MP4 scaled up in whole even pixels (`diorama/video.ts`: WebCodecs H.264 and the `mp4-muxer` package, lazy-loaded). - Open a model (Scene tab; issue #164): `splat-engine/meshFile.ts` (pure, tested) reads an .obj (with its .mtl's `Kd` if picked with it) or a .glb (every triangle primitive placed by the node tree, COLOR_0 times the base color, the base color texture kept for the page to decode into a `Texture`); `splat-engine/meshShape.ts` (tested) turns a closed mesh into a `Shape` (exact distance in a band round the surface on a grid half a cell apart, inside or out by crossings along x, trilinear between) and `meshColor` paints from the nearest triangle; `diorama/model.ts` makes it a `Diorama` (fitted to `MODEL_SIZE` on a plinth, turning once a loop, a palette picked from its colors at three light levels). - Scenes are `Diorama`s in `diorama/scenes.ts` (`?scene=<id>` picks one): the lighthouse is code (`diorama/scene.ts`); the campfire, the dragon, the bee, the stone hand, the reef, the storm octopus, the owl and cauldron, the sky islands, the snail house, the lantern spider, the sunrise window, the heron hut, the garden crocodile, the lantern grove, the sprout lab, the pumpkin watch, the windmill, the ruined chapel, the crystal cave, the desert canyon and the snowed-in cabin are descriptions, data alone (`diorama/scenes/*.ts`, typed `SceneDoc`), which `splat-engine/sceneDoc.ts` checks (`checkScene`, messages as `where: what`) and compiles (`compileScene`: spec, poser, lights, look). A new shape, paint or move needs a case in the type, the checker and the builder, and a line in that guide.

- Weather that lands (issue #174, `splat-engine/weather.ts`, pure and tested): `groundUnder` steps down by the shapes' own distances to the first surface. Rain, snow and leaf specks with `land` fall to whatever stays put under where they come down (parts on no bone or one that only sways; worked out once in `compileScene`), lie and go (`fallAt`, size 0 at both ends of each life so it loops; snow melts in quickly because a flake lying on snow gets a ring of part lines), blown by `wind` (rain leans along it); leaves flutter and lie flat. `drift` is a layer over the parts before it: `driftField` deepens snow behind anything upwind and wide (`WIDE`; a post doesn't shelter), scours what stands above the ground upwind, takes it off steep faces, thins it on a `path`, then blurs it. `frost` (`frostPlan`) grows strokes in a plane, side branches on alternate sides every other step, `t` its order of growth; `stage` cuts a share so parts can sprout in turn. - Ink (issue #112): a part's `ink` marks some 4×4 blocks of grid cells with one mark from `INK_MARKS` (`inkedAt`: blocks in each row shifted at random, each mark picked, turned and flipped per block, so nothing repeats; `UPRIGHT` kinds only flip side to side), in `inkOf` (a much darker step) unless given a color. - Glass (issue #113): pixel mode cuts anything faint, so water, ice and glass are baked, not drawn see-through: a `glass` part's cells take what the line from `VoxelSpec.eye` (the scene's camera) meets behind them (`see`; a darker step of their own color where it leaves the part with nothing met) and what their mirror line meets (`mirror`, Fresnel-ish), both from `lookAlong` (paint plus sun, no shadows), shared by cells two a side (`glassSeen`). Lights must loop too.

- A shape thinner than the grid can miss every cell: the scene sizes thin parts from `spacing` (`thin`), and `scene.test.ts` checks every part caught some.
- Painted light and air (Silicon Jungle gap list, issues #106 to #108): `buildVoxels`'s light takes `ramp` (shade turns its OKLab hue toward violet, full sun toward yellow; `bakedColor`), `crevice` (`openness` looks a short way out along the normal; it darkens only the ambient share, so a sunlit corner stays bright) and `wear` (edges lighten, from the Laplacian of the samples the normal came from); a part's `grime` gathers where it is shut in. From blobs alone, so a thin bar through a floor (few blobs near the surface) can slip by. ## Scan Studio (`/experiments/scan-studio/`, `src/blobscape/ScanStudio.tsx`, `src/blobscape/scan/`)
- Opens a phone splat scan (.ply/.spz/... via `readSplatFile`, capped at 800k blobs, 300k on phones), or a made-up sample mug (`scan/sample.ts`, with floaters and haze, tipped off level).
- `clean.ts` is pure and tested: `findFloor` (RANSAC; a floor must hold `minShare` of the blobs and have almost none past it, so a lid or a mug's coffee isn't taken for the table), masks for floor, crop, faint, huge and floaters (grid clumps, cells grown until a typical blob's cell is full). `studio.ts` turns the scan level and to `WORK` units (`working`), combines the masks (`cleanMasks`), previews (cut blobs in faint red), packs the result (`finish`: on y = 0, `FINISHED` units) and places the light presets round the kept blobs (`lightsFor`).
- The view is `CreatureStage` with `{ lights: true }`; the scan is one still bone (`stillActor`) rebuilt when the masks change (sliders apply 180 ms behind). "Keep the lighting" bakes the lights into colors with `splat-engine/light.ts`, the CPU twin of the engine's `lit`/`blobNormal` (change both).
- Colliders (issue #238; `splat-engine/colliders.ts`, pure and tested, in the package): a `Collider` is a box, ball or upright cylinder turned only about the upright. `groundOf` is the `Ground` `plantFeet` takes (`groundBelow` leaves out tops too high to step onto), `pushOut` keeps a point out, `pickCollider` finds one by a ray, `handlesOf`/`resized` are the size handles, `wireOf` its lines for drawing, `guessColliders` the table slab and a box round the kept blobs, and `writeColliderGlb`/`readColliderGlb` a .glb of ordinary nodes with a mesh each (`extras.blobscape_collider` is what we read back; `KHR_implicit_shapes` and `KHR_physics_rigid_bodies` are written as used, not required). Scan Studio's Colliders tab (`scan/Colliders.tsx`; my tab name, not Matt's yet) keeps them in the view's units (the table at y = 0) and draws them as an SVG over the canvas through `Stage.screenAt`; only the handles take the pointer (white dots size, the coral dot slides it level), and a click that hardly moves picks the shape under it. Saving and the hand-off move them as `finish` moves the blobs (`finishing`, then `placed`); opening a file moves them back. In the sandbox (`handOff`'s third argument) they last while that scan is the scene: `poseAll`'s `ground` stands each creature on the highest top under it, and `standOn` runs `plantFeet` for a two-legged body with the elf's bone names, so each foot finds its own height.
