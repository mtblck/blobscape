# Blobscape

Blobscape (blobscape.dev): lessons, a sandbox and small experiments with Gaussian splats. One Vite
multi-page React app, one Vercel project, served from the root. See README for the why behind the choices.

## Commands
- `npm run dev`, `npm run build` (hosting:check + tsc, vite build, then `scripts/prerender.ts`), `npm run preview` (production headers)
- `npm test` — unit tests for the pixel pipeline and the Gaussian fitter (node --test, no GPU)
- `npm run build && npm run verify` — real Chromium against dist with vercel.json headers, plus axe; screenshots in verify-shots/

## Load-bearing
- Vite `base: '/'`, `outDir: 'dist'`, Vercel `trailingSlash: true` (every page is a folder with an index.html). `hosting:check` enforces it.
- Blobscape's pages are paths (`/`, `/lessons/`, `/lessons/<id>/`, `/sandbox/`, `/experiments/`, `/experiments/creature/`, `/engine/`, `/engine/rigged-splats/`, `/contact/`), parsed in `routes.ts`. `scripts/prerender.ts` writes each one's HTML (title, description, canonical, og, JSON-LD, readable content) from the built `dist/index.html`, plus 404.html, sitemap.xml, robots.txt. Pages that draw no WebGL at first (`FROM_APP`: home, lessons, experiments, engine, spec, contact, 404) are rendered by the app itself through Vite's SSR loader (`src/blobscape/ssr.tsx`, `<App route>`), marked `data-ssr` and hydrated by `main.tsx`, so the first paint is the page and doesn't jump; anything that reads the browser (storage, `document`) must read it in an effect, not while rendering, or the hydrated page keeps the prerendered value. The WebGL pages get a readable stand-in (`content()`). Both fonts are preloaded, and `theme.css` has per-weight metric-matched fallbacks (`Figtree Fallback`, `Fredoka Fallback`) so text doesn't reflow when they arrive. A new page needs a case in `routes.ts`, `meta.ts` and `prerender.ts`.
- `useLinkNavigation` turns plain clicks on links to Blobscape pages into in-app navigation; tools and other sites load normally. Old `#/…` links are rewritten to paths on load.
- CSP needs `'wasm-unsafe-eval'` and `worker-src blob:` (Spark decodes in WASM, sorts in a blob worker).
- Every experiment lives under `/experiments/` (old `/creature/` and `/tools/*` addresses redirect there). Add a new tool: `experiments/<name>/index.html` + `src/<name>/`, an input in vite.config.ts, an entry first in `EXPERIMENTS` (src/blobscape/site.ts: front page, menu, the Experiments page; newest first) with its `published` and `updated` days (the footer's `NEWEST_EXPERIMENTS` and the Experiments page's order come from `published`; bump `updated` only for a change a visitor would see, not site-wide work; the dates show on the cards, on each experiment's crumb line via `Crumbs`, in its JSON-LD and as its sitemap lastmod) and the sitemap list in prerender.ts. Every page renders `SiteHeader` (src/shared) first, puts its content in `<main id="main">` for the skip link, and ends with `Footer` (src/shared).
- Brand: colors are hex tokens in `src/shared/theme.css` (light default, dark three times: system, forced, `.case`; keep them in step). Blob coral `#f2553a` (`blob`) is for the logo and big shapes, never small text; `accent` is the text-safe coral. Headings `font-display` (Fredoka 600), text Figtree. Logo shapes in `src/shared/logoPaths.ts`; don't recolor, stretch or add effects. The theme choice is stored as `blobscape-theme`.
  Tabs, sliders, chips and toggles live in `src/shared/ui.tsx`; reuse them so every experiment shares the same hover and cursor states.
- Every experiment page uses one layout, `Workbench` (src/shared/Workbench.tsx): the preview on the left (two thirds, 4:3, sticky; on phones on top at 45% of the screen, in `svh` so it does not change height as the address bar hides), one options panel on the right split into tabs (each tab's box is `TAB_SECTIONS`: every direct child is a section with a rule above it, so wrap a multi-part section in one div), an optional `footer` under the tabs, and a full screen button on the preview (it fills the window where the browser has no element full screen, as on iPhones; `fullScreenAt` moves it off a game's HUD). Anything that does not act on the preview goes in a card below. While a view waits it shows `LoadingMark` (src/shared/BlobLoader.tsx): three blobs moved only by `transform` on their own elements, so the compositor keeps them going while a build holds the main thread; the page's sr-only status line says what it waits for. The tab names are Matt's (project memory `experiment-layout`); verify checks them and that the columns are the same size on every page, and its `tabClick` opens a control's tab before clicking it.

## Splat to Sprite
- three.js + Spark (`@sparkjsdev/spark`). Live view = scene SparkRenderer; sprite = a second, offline SparkRenderer with a render target, sorted for the sprite camera (`engine.ts`).
- Read the target with sync `readRenderTargetPixels`; Spark's async `readTarget()` stalled in headless Chromium.
- The viewport only renders when invalidated or while Spark is mid-sort; Spark picks up a finished sort only on the next render, so don't stop on `framesLeft` alone.
- Sheet JSON mirrors Tinkerkit's `SpriteSheet` (tinkerkit packages/format/src/spritesheet.ts, format 71); rows down/left/right/up.
- Commit as `mtblck <105079242+mtblck@users.noreply.github.com>` or Vercel blocks the deploy.

## Fit a Picture
- `fit.ts` is the whole trainer (render, loss, hand-derived backward pass, Adam, prune, densify) on typed arrays; it runs in `trainer.worker.ts` and in Node tests. Change a gradient → `npm test` (finite-difference check).
- Blobs add up (no sorting): pixel = Σ opacity·color·falloff. Params are log scales, angle, and sigmoid color/opacity.
- The worker posts a frame ~30×/s with the display image, new losses and events; the page keeps losses in a ref buffer, not state.

## Splat engine (prototype, `src/splat-engine/`, test page `/engine-lab/`)
- The engine lab is deliberately unlisted (noindex, no hub card): it's a test bench, not an experiment.
- `Skeleton.place` is where an actor stands; poses (`offset`, `rotation`, `reset()`) never touch it.
- Our own renderer for animated splats, on three.js's WebGPURenderer (TSL). `SplatWorld` holds every blob of every actor. WebGPU, per frame: deform compute (bones → world center + covariance), project compute (→ screen center + ellipse axes, writes sort keys and histogram), `DepthSort` prefix + scatter (`sort.ts`, one counting sort over the whole scene), then a lean instanced draw. Projection/shading follow three's `GaussianSplat` (MIT). A still object is one bone.
- The sort must give the same order for the same view: the scatter's threads race within a depth bin, so `DepthSort`'s settle pass orders each small bin by index, and `setView` keeps bins a fixed width anchored in depth. Break either and hard edges flicker in pixel mode (verify draws one moment twice and compares).
- WebGL has no compute: the vertex shader runs `deformBlob` + `projectSplat` per corner (like a skinned mesh), and the CPU only moves centers (`skinCenters`) and sorts. Both backends share those TSL helpers, so change them once.
- Quads shrink with opacity (`placeQuad`): a blob's quad reaches only as far as it stays above 1/255.
- `rig.ts` `skinBlob` is the CPU twin of the deform pass (used by `checkAgainstCPU`; `skinCenters` is its fast center-only twin, tested against it); change one, change both. Weights go to the GPU as bytes summing to 255 (`packWeights`) and the CPU twin reads the same bytes.
- A compute stage may bind only 8 storage buffers on many phones: joints+weights share one buffer for that reason.
- Headless software WebGPU renders but can't present to a canvas: the lab's `offscreen=1` draws to a target and copies frames to the page; verify uses it.
- Rigged files: `glb.ts` writes KHR_gaussian_splatting + standard glTF skins/animation + `BLOBSCAPE_gaussian_skinning` (used, not required). three.js's loader opens them as a still splat (verify checks).
- The pixel pipeline lives in `src/splat-core/pixel.ts` (shared by Splat to Sprite and the engine's walk sheet); color transfer functions, `SH_C0` and the render-target readback (`readbackToSrgb`) in `splat-core/color.ts`.
- Status and gaps: `docs/engine-prototype.md`.
- Picking, mixing and IK (CPU, tested): `pick.ts` `pickActors` takes a ray back through each blob's blended skin matrix into its rest frame and tests it there with `rayHit` (the nearest blob, its heaviest bone, its part); `mix.ts` has `takePose`/`blendPose`/`addPose` and a `Mixer` (weights that sum to 1, crossfades; each move starts from rest); `ik.ts` has `twoBoneIK` (the end is a rest point the lower bone carries, the knee keeps the side it bends), `lookAt`, and `plantFeet` (hips by the smallest leg change, each leg to its own ground plus the walk's lift, feet tilted to the slope). Splat Creatures' tap-a-bone uses `pickActors` and tints the GPU colors only (`CreatureStage.highlight`; the actor's own colors stay for files and sheets). Feet on the ground (lesson 13, `lessons/Feet.tsx`, `feet/stand.ts` pure and tested) is the elf walk on steps, a slope or rocks through `plantFeet`.
- Live lights: `new SplatWorld(actors, { lights: true })` then `setLights(lights, ambient)` (up to `MAX_LIGHTS` point lights). Color = baked color × (ambient + Σ lights by distance and facing); a blob's normal is its covariance's thinnest axis (`blobNormal`, from the adjugate). WebGPU runs one light pass per frame into its own buffer, which the draw reads in place of the packed color (no extra draw bindings); WebGL lights per corner in the vertex shader. Off by default. Lamp shadows: an actor's `seen` (from `buildVoxels` given `lamps`, one byte per light 0 to 3, 255 = fully seen) scales each of the first four lights in `lit()` and in the CPU twin `lightAt`; a scene light opts in with `shadows: true`.
- Level of detail (`lod.ts`, tested): `setDetail(actor, keep)` or `world.autoDetail = DETAIL` (each actor about one blob per pixel of its disc on screen, from `boneSphere`s carried by the bones). The share dropped rides in each bone matrix's unused float 3; `deformBlob` and `deformCPU` drop blobs ranked under it by `lodRank` (the same hash on both) to zero covariance and grow the rest by 1/keep. Change both. Off on every page; the lab has `?lod=1`.
- Rigged-splat file rule (spec draft): `docs/rigged-splats.md`, also shown as the page `/engine/rigged-splats/` (`Spec.tsx`; `markdown.ts` turns the file into HTML for the page and the prerender, knows only what that file uses and escapes the rest; sample files in `public/rigged-splats/`, linked from the doc as `../public/…` and rewritten by `specLink`); the skinning extension object sits inside the primitive's `KHR_gaussian_splatting` object. The lab's `?which=spark` runs the same fox on Spark's `SplatSkinning` (bones rest at the origin; see `sparkBones.ts`).

## Clockwork (`/experiments/clockwork/`, `src/blobscape/Clockwork.tsx`, `src/splat-engine/clockwork.ts`)

## Shape Shifter (`/experiments/shape-shifter/`, `src/blobscape/ShapeShifter.tsx`, `src/splat-engine/shift.ts`)
- One creature turning into another (`?from=<id>&to=<id>`, from `CREATURES`). `shift.ts` is pure and tested: `sized` brings each creature to one size on the floor, `pairUp` gives every blob a partner (by place: both lists halved by rank across the longest way of the two together, again and again; the creature with fewer blobs lends some twice; 'random' is there to show what place is for), `shiftBlobs` blends each pair (center along the path, sizes by ratio, facing by the short way, color and opacity straight; paths straight, swirl, melt, burst; orders together, rise, scatter), and `amountAt`/`timeAt` are the there-and-back loop.
- No bone moves: the blobs are blended on the CPU into one `Blobs` on a still bone, and the poser calls `CreatureStage.refresh` (`SplatWorld.refresh`), which packs the actors' blobs into the GPU buffers again. The counts must not change. The poser skips frames where nothing changed (the holds at each end).
- Creatures are cut once per detail level and kept (`cut`), a moment apart so `LoadingMark` keeps moving. Verify drives `window.__shift.stage.frame(seconds)` with `?offscreen=1`, on both backends.

## Forest Walk (`/experiments/forest-walk/`, `src/blobscape/forest/`)
- The elf and the whole forest are one `SplatWorld`, built once; walking only re-poses. Changing detail, season or the elf's look rebuilds it.
- The path is a ring of `RING` tiles; `pathX` repeats every `PERIOD` so tile i always reuses ring slot i % RING (its ground moves by whole periods). Plants per tile are fixed per kind (`PER_TILE`), and `layout(i, seed)` says which stand where, so walking back finds the same forest.
- Growing is bone `size` from 0 (`sprung`), swaying is a turn on upper bones; hidden plants have `rootScale` 0 and stand at the elf so they don't stretch the scene bounds.
- Mist: `SplatWorld.setFog` (both backends, by view depth) and the floor plane's own fade must use the same color and distances.
- `world.ts`/`forest.ts` are pure and tested in Node; verify drives `stage.frame(seconds, input)` with `?offscreen=1`.

## Dungeon Run (`/experiments/dungeon-run/`, `src/blobscape/DungeonRun.tsx`, `src/blobscape/dungeon/`)
- `game.ts` is the whole game in plain numbers (hero, slimes, bolts, waves; circles on the floor for every hit and push), stepped by `step(dt, input)` and tested in Node. `dungeon.ts` builds every actor once and poses them from the game; nothing is rebuilt mid-fight.
- Slimes are pooled per color (`RULES[kind].pool`; colors are baked into blobs, so a slime can't change color). A pool slot not in use is hidden with `rootScale` 0 at the hero. Each slime carries 16 shard bones at size 0 that become the burst.
- The hero is the elf (`makeElf` on `ELF_BONES` and two more) plus a `sword` bone on the right hand and an `orb` bone on the left; swings and casts are `aim`s layered on the idle/run blend. The swing is a low sweep in front, right to left at about knee height, because slimes are low: Matt found the first one, a cut from over the shoulder, passed above them and read as a miss. A test holds the blade under a slime's top and at `SWORD_REACH` through the hit window; a swing also turns to a slime within `LUNGE_RANGE` and steps in when the blade would fall short.
- Light is Baked (torchlight in the hall's colors, `torchLight`) or Live (the engine's lights: torches, the orb, bolts, bursts, from `Dungeon.lights()`; the hall is built unlit). Live is the default on WebGPU, Baked on WebGL. `?webgl=1` forces the WebGL backend for testing. The flames are bones. Verify drives `stage.frame(seconds, input)` with `?offscreen=1`.
- Fire and frost (K/E and L/Q, the Fire and Frost buttons): `ground.ts` (pure, tested) is the floor as a grid of half-meter cells stepped at a fixed tick, so the same bolts give the same floor. A bolt lights a patch where it lands and it spreads a few cells; fire burns out and leaves `char` (which can't catch again for a while), frost lies longer, and the two cancel. The game only asks `ground.at(x, z)`: fire burns slimes and the hero, frost slows them. Drawing is `elements.ts`: `paintFloor` recolors the floor's own blobs from the grid whenever `ground.version` changes and the stage sends just the colors up with `SplatWorld.recolor(actor)`; flames and clumps of ice are built once, a bone each at size 0, and stood on the strongest cells by `Patches` (they hold their cell so they don't hop). Bolts are pooled per element, like slimes per color.
- Crates, urns and barrels (`PROPS` and `PROP_RULES` in `game.ts`, drawn by `breakables.ts`): whole, each is a circle nothing walks through; the sword, a bolt or fire underfoot (not urns) wears it down. A crate gives health, an urn magic, a barrel lights the floor and throws back the slimes near it, so no barrel stands within a swing of another prop (tested). Built like a slime: a body bone and ten piece bones at size 0; broken, `pieceFlight` gives each piece's place from the blow's way and the time alone, and they lie there until the next wave puts the hall back (skipping any spot someone stands on).
- The sandbox's Creatures tab also adds `PROPS` (`src/blobscape/props.ts`): Dungeon Run's slime and Clockwork's watch, written as `Species` (the watch's move ignores its clock and shows the time now).

## Pixel Diorama (`/experiments/pixel-diorama/`, `src/blobscape/PixelDiorama.tsx`, `src/blobscape/diorama/scene.ts`)
- Pixel-art scenes from splats, in three parts. `splat-engine/voxel.ts` (pure, tested) cuts shapes given as distance functions into one grid shared by every part; each surface cell is one solid disc lying on the surface, on one bone, with sun, ambient and cast shadows baked into its color. Lit colors stop at `LIT_MAX`; only `glow` parts go brighter, and pixel mode's `GLOW_FROM` sits just above it, so a lamp glows and a white wall doesn't. Keep the two in step.
- Pixel mode is `CreatureStage.setPixels(look, size)`: `splat-engine/pixelPass.ts` draws the scene small into a target, then one full-screen pass does alpha cut, glow, edge lines inside the scene (`edges`: the darker side of an OKLab jump over `EDGE_JUMP`), OKLab palette + Bayer dither, a silhouette outline and an optional `sky` (a top-to-bottom gradient on empty pixels, dithered into the palette; leave it out for sprites; its optional third value, a scene's `skyReach`, is how far down the blend runs before it is all the bottom color), scaled up by a whole number of device pixels. `pixelArt` in `splat-core/pixel.ts` is its CPU twin (change one, change both; verify compares them on WebGPU and WebGL). `stage.pixelFrames()` reads the small frame and the art back. The pass always draws into its `art` target (kept in sRGB, so palette colors are stored exactly) and the screen gets a plain scaled copy. It keeps the art of the frame before as well: a look with `steady` (the page's Steady pixels switch, `STEADY`) lets a scene pixel keep its palette color unless another is clearly closer, which stops pixels between two colors flipping as lights flicker and the view swings. Only a pixel that is scene now can stick: sky and glow-only pixels never do (a pixel the scene has left would keep its color). `?steady=0` starts with it off. `CreatureStage.step` (the page's Motion choice: Smooth, 12 or 8 a second) holds frames: the pose only moves on every `step` seconds and nothing is drawn in between, which is what stops edges crawling while a view swings; `stage.time` is the held time. `pixelArt(f, look, before)` does the same given `pixelFrames().before`. Lines between parts (`PixelLook.parts`, with or without `edges`): the pass draws the blobs a second time into `ids` as a map of parts (`SplatWorld.parts`: every blob a hard disc in its part's flat color, from `Actor.partOf`, reusing the frame's sort), and a pixel beside another part whose color is too close for a color line takes a line when its part is the lower-numbered (by number, not lightness, so the line keeps its side as lights flicker). `pixelArt`'s fourth argument is that map (`pixelFrames().parts`).
- Every scene also has a recorded loop (`public/loops/<id>.webp`, lossless, one pass at 12 fps, plus `<id>.png`, its first frame, shown under reduced motion), recorded from the build by `node --experimental-strip-types scripts/record-loops.mjs [out] [ids…]` (stepped with `stage.frame(t)`, so a loop joins up; about 10 minutes a scene here; also writes a 3× MP4 for posting). `diorama/Gallery.tsx` shows them under Pixel Diorama (a tile picks the scene) and on the engine page (`ENGINE_LOOPS`); `diorama/loops.ts` lists them apart from `scenes.ts` and `loops.test.ts` keeps the lists in step, so a new scene needs a recorded loop. Record a scene again after a change you'd see.
- Under the view is one short line (blobs, the art's size, a frame's size as a PNG) and a Full details button that opens `diorama/SceneDetails.tsx`, a native modal `<dialog>` of readouts built from `SceneFacts`: the three sizes (description as JSON, a frame as a PNG, the splats at 56 bytes a blob) on a log scale, tiles for the scene and the picture, and the palette. The page measures a frame every three seconds, not every frame. A new stat goes in `SceneFacts`.
- In the pass, `cell.y` counts from the bottom of the picture on screen and in a target alike; anything that depends on the row itself (the dither pattern, the sky) uses `row`, the CPU twin's y.
- Surface texture (bricks, tiles, planks, strata) is the part's `color(p, n)` function, sized from `spacing` so a line is at least a cell wide. A gray the palette lacks snaps to a brown: keep neutral steps in a palette that has to show stone.
- Scenes are `Diorama`s in `diorama/scenes.ts` (`?scene=<id>` picks one): the lighthouse is code (`diorama/scene.ts`); the campfire, the dragon, the bee, the stone hand, the reef, the storm octopus, the owl and cauldron, the sky islands, the snail house, the lantern spider, the sunrise window, the heron hut, the garden crocodile, the lantern grove, the sprout lab, the pumpkin watch and the windmill are descriptions, data alone (`diorama/scenes/*.ts`, typed `SceneDoc`), which `splat-engine/sceneDoc.ts` checks (`checkScene`, messages as `where: what`) and compiles (`compileScene`: spec, poser, lights, look). It fattens anything thinner than the grid, and every move takes a whole number of `times` per loop. How to write or prompt for one: `docs/scene-descriptions.md`. A new shape, paint or move needs a case in the type, the checker and the builder, and a line in that guide.
- The lighthouse is cut on a grid `FINER` (0.72) times the detail level's spacing, on a small round sea: its island is small beside the other scenes' subjects, so at the shared spacing its bricks and windows were a cell or two and read as blobs. A subject should fill the scene; open ground or water only spends cells.
- A scene's `camera.swing` rocks the view once a loop (off under reduced motion): the poser writes `stage.orbit` from the page's own orbit state (`swung`), so the user's orbit lives in React state and is never read back from the stage. A scene with no `sky` starts with "Sky behind" off (`finish.sky`).
- A `union`/`join` is walked as one box: joining far-apart shapes (all the stars) makes the build slow; keep them separate parts.
- A shape thinner than the grid can miss every cell: the scene sizes thin parts from `spacing` (`thin`), and `scene.test.ts` checks every part caught some.
- Painted light and air (Silicon Jungle gap list, issues #106 to #108): `buildVoxels`'s light takes `ramp` (shade turns its OKLab hue toward violet, full sun toward yellow; `bakedColor`), `crevice` (`openness` looks a short way out along the normal; it darkens only the ambient share, so a sunlit corner stays bright) and `wear` (edges lighten, from the Laplacian of the samples the normal came from); a part's `grime` gathers where it is shut in. All off by default (creatures don't use them); scenes get `PAINTED` unless they set their own. `beams` light what they land on (faces turned back up the beam). A scene's `air`: `haze` (the engine's distance fog, measured from the view's target, set by the page as the view moves), `mist` (loose blobs under `LOOSE_MAX` opacity so the map of parts never sees them, on a few drifting bones), `shafts` (become beams) and `specks` (a bone per speck, `~speck<n>`, posed in `poseSpeck`, not counted against the 64-bone limit). Mist tints what is under it, so keep it thin and close in color to the ground. A creature taken from a scene (`sceneCreature`) leaves the air behind. A scene's `cover` (issue #110: `snow` on tops whose sky is open, by a march straight up; `moss` by `openness` and facing; `dust` on any upturned face; all broken up by `patches` noise) is mixed into the paint before light in `coverAt`; `glow` and `bare` parts skip it, and so does a creature taken from a scene.
- The scene is posed from the time alone (`poseDiorama`) and repeats every `LOOP` seconds: every motion must fit a whole number of times into it. The lamp's light is two live point lights (`lampLights`) set in the same poser. `?webgl=1` forces the WebGL backend.

## Scan Studio (`/experiments/scan-studio/`, `src/blobscape/ScanStudio.tsx`, `src/blobscape/scan/`)
- Opens a phone splat scan (.ply/.spz/... via `readSplatFile`, capped at 800k blobs, 300k on phones), or a made-up sample mug (`scan/sample.ts`, with floaters and haze, tipped off level).
- `clean.ts` is pure and tested: `findFloor` (RANSAC; a floor must hold `minShare` of the blobs and have almost none past it, so a lid or a mug's coffee isn't taken for the table), masks for floor, crop, faint, huge and floaters (grid clumps, cells grown until a typical blob's cell is full). `studio.ts` turns the scan level and to `WORK` units (`working`), combines the masks (`cleanMasks`), previews (cut blobs in faint red), packs the result (`finish`: on y = 0, `FINISHED` units) and places the light presets round the kept blobs (`lightsFor`).
- The view is `CreatureStage` with `{ lights: true }`; the scan is one still bone (`stillActor`) rebuilt when the masks change (sliders apply 180 ms behind). "Keep the lighting" bakes the lights into colors with `splat-engine/light.ts`, the CPU twin of the engine's `lit`/`blobNormal` (change both).
- Verify drives it with `?offscreen=1`: sample leveled, red cut view, lamp relights, .ply download reopens with the same count, and Open in the sandbox hands it over.
