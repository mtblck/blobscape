# Blobscape

Blobscape (blobscape.dev): lessons, a sandbox and small experiments with Gaussian splats. One Vite
multi-page React app, one Vercel project, served from the root. See README for the why behind the choices.

## Commands
- `npm run dev`, `npm run build` (hosting:check + tsc, vite build, then `scripts/prerender.ts`), `npm run preview` (production headers)
- `npm test` — unit tests for the pixel pipeline and the Gaussian fitter (node --test, no GPU). Keep them light (Matt, 2026-11-21: the islands' tests had grown to over 20 minutes): files run side by side but a file's tests run one after another, so plan or cut a heavy thing once a file and share it, cut far coarser than the page does (the islands' `cut.test.ts` is a ninth of the blobs), build no message for a check that passes inside a loop over blobs (`if (!ok) assert.fail(...)`), and give a test that must stay heavy a file of its own. `node --test --experimental-strip-types --test-reporter=spec <file>` prints each test's time
- `npm run check` before merging: `npm test`, the build, then `verify --changed` (only the browser checks the changed files reach, by imports; a file half the checks import runs the `core` set, `--wide` for all). All three print a line or two when they pass and each failure once; the rest is in `verify-shots/` (`tests.txt`, `build.txt`, `report.txt`): read the summary, open a report only for a failure it names (`npm run test:loud`, `verify --loud` for everything). A failed browser check runs once more alone; one that then passes is `flaky`, not a failure. `.github/workflows/check.yml` runs the unit tests and the build on every PR, and every browser check nightly on main (a failed night opens the issue "Nightly browser checks are failing", which closes itself when green; look at it before blaming a branch for a failure it didn't cause); a full run takes about 40 minutes there, so PRs don't get one: run `npm run check` yourself. Full `npm run build && npm run verify` (every check, three at a time) for build, hosting or harness changes, or when asked. Real Chromium against dist with vercel.json headers, plus axe; screenshots in verify-shots/. Checks live in `scripts/verify/checks/` with the source files they cover; a new page or experiment needs one. See docs/testing.md.
- Releases: for anything a visitor would notice, add a new file `changes/<a-few-words>.md` holding the changelog line (plain text, no heading; see `changes/README.md`). Never edit CHANGELOG.md in a feature PR: every PR adding a line in the same spot put the others in conflict (Matt agreed to the change, 2026-11-19). `npm run release -- x.y.z` joins the files into CHANGELOG.md, removes them and makes the release PR; merging it to main makes `.github/workflows/release.yml` tag it, make the GitHub release (sessions can't push tags) and publish `@blobscape/engine` at the same version once its manifest isn't `private` (npm org `blobscape`; by npm trusted publishing, no stored token). Merge a release PR only when Matt says go. See docs/releasing.md.

## Load-bearing
- Vite `base: '/'`, `outDir: 'dist'`, Vercel `trailingSlash: true` (every page is a folder with an index.html). `hosting:check` enforces it.
- Blobscape's pages are paths (`/`, `/lessons/`, `/lessons/<id>/`, `/scene-creator/`, `/experiments/`, `/experiments/sandbox/`, `/experiments/creature/`, `/experiments/four-ways/`, `/engine/`, `/engine/rigged-splats/`, `/contact/`, `/whats-new/`, `/whats-new/<id>/`), parsed in `routes.ts`. `scripts/prerender.ts` writes each one's HTML (title, description, canonical, og, JSON-LD, readable content) from the built `dist/index.html`, plus 404.html, sitemap.xml, robots.txt. Every page is rendered by the app itself through Vite's SSR loader (`src/blobscape/ssr.tsx`, `<App route>`), so the first paint is the page and doesn't jump (verify's `site` check compares the heading's place before and after the app starts). Pages that draw no WebGL at first (`HYDRATED`: home, lessons, experiments, engine, spec, docs, contact, 404) are marked `data-ssr` and hydrated by `main.tsx`; on those, anything that reads the browser (storage, `document`) must read it in an effect, not while rendering, or the hydrated page keeps the prerendered value. Lessons and the WebGL experiments read the address and saved progress as they start, so `main.tsx` draws them afresh over the prerendered page (never hydrate them); on the server they see a plain address (`renderPage` stands in a `location`), so a page must render without `window`: guard `matchMedia` with `typeof window`, and keep everything else that needs the browser in effects. Both fonts are preloaded, and `theme.css` has per-weight metric-matched fallbacks (`Figtree Fallback`, `Fredoka Fallback`) so text doesn't reflow when they arrive. A new page needs a case in `routes.ts`, `meta.ts` and `prerender.ts`.
- `useLinkNavigation` turns plain clicks on links to Blobscape pages into in-app navigation; tools and other sites load normally. Old `#/…` links are rewritten to paths on load.
- CSP needs `'wasm-unsafe-eval'` and `worker-src blob:` (Spark decodes in WASM, sorts in a blob worker).
- Every experiment lives under `/experiments/` (old `/creature/`, `/sandbox/` and `/tools/*` addresses redirect there). Logo shapes in `src/shared/logoPaths.ts`; don't recolor, stretch or add effects. The theme choice is stored as `blobscape-theme`.

## Splat to Sprite
- three.js + Spark (`@sparkjsdev/spark`). Live view = scene SparkRenderer; sprite = a second, offline SparkRenderer with a render target, sorted for the sprite camera (`engine.ts`).
- Read the target with sync `readRenderTargetPixels`; Spark's async `readTarget()` stalled in headless Chromium.
- The viewport only renders when invalidated or while Spark is mid-sort; Spark picks up a finished sort only on the next render, so don't stop on `framesLeft` alone.
- Sheet JSON mirrors Tinkerkit's `SpriteSheet` (tinkerkit packages/format/src/spritesheet.ts, format 71); rows down/left/right/up.
- Commit as `mtblck <105079242+mtblck@users.noreply.github.com>` or Vercel blocks the deploy.

## Fit a Picture
- `fit.ts` is the whole trainer (render, loss, hand-derived backward pass, Adam, prune, densify) on typed arrays; it runs in `trainer.worker.ts` and in Node tests. Change a gradient → `npm test` (finite-difference check).
- Blobs add up (no sorting): pixel = Σ opacity·color·falloff. Params are log scales, angle, and sigmoid color/opacity.
- The worker posts a frame ~30×/s with the display image, new losses and events; the page keeps losses in a ref buffer, not state.

- Morphs (lesson 15): `splat-engine/morph.ts` (pure, tested) is blend shapes for blobs. A target holds, per blob, a center `delta` and `grad` (the morph's local 3×3 map minus identity, found by nudging the rest center in `targetFrom`); `applyMorphs` adds the weighted deltas and pushes each covariance through J = I + Σ w·grad ('centers' mode moves centers only, for the lesson's left view). A morph with several `targets` reaches them in turn (`shares`; tested, no lesson uses it now). The lesson morphs on the CPU; the engine also does it on the GPU (`Actor.morphs`, `SplatWorld.setMorphWeights`, up to `MAX_MORPH_TARGETS` targets in the world): on WebGPU a pre-pass writes each blob's morphed center and the Cholesky factor of its morphed covariance, and the deform pass reads those instead of the rest center, scale and rotation (so it stays within 8 storage buffers); on WebGL the CPU runs `applyMorphs` and uploads the shapes. `applyMorphs` is the twin; verify compares them with `checkAgainstCPU` on the puffer. In files (`glb.ts`, spec section Morphs): standard glTF morph targets (`POSITION` deltas, sparse when under half the blobs move, `weights` channels on the mesh node) plus our `BLOBSCAPE_gaussian_morphs` extension (a `SHAPE` MAT3 per target, G = J − I by columns, and which targets are one morph's in-betweens; `targetWeights`/`morphWeight` convert). `Clip.weights` keys each morph per time (`recordClip`'s `weights`, `sampleWeights`). `CreatureStage` hands an actor's `morphs` to the world and sets their weights each pose (`setMorphWeights` while no clip keys them) and Splat Creatures plays them; the sample is `public/rigged-splats/puffer.glb` (`PUFFER_MOVES`). The lesson's subject is a pufferfish, `splat-engine/puffer.ts` (voxel discs; puff and spikes morphs, and two tail morphs, a bend to each side along the tail's length from a base that stays in the body, driven by one Swing slider through `tailWeights`; the slider runs to 150% for the last goal, where the tail grows instead of curling further; eyes, fins, mouth and spikes ride on the body, shifted whole by the puff so they never stretch; spikes are cut at full length and the rest shape keeps them as nubs), with the lesson's measures `flankSpread`, `spikeLength` and `tailLength`. It was a face first: Matt found the lids and stretched eyes looked wrong, so keep subjects where a morph can't look uncanny. The tail was a rigid turn about its root first, which Matt rejected as not how tails work: a part that swings must bend from a fixed base.

## Splat engine (`src/splat-engine/`, test page `/engine-lab/`)
- The engine lab is deliberately unlisted (noindex, no hub card): it's a test bench, not an experiment.
- `Skeleton.place` is where an actor stands; poses (`offset`, `rotation`, `reset()`) never touch it.
- Our own renderer for animated splats, on three.js's WebGPURenderer (TSL). `SplatWorld` holds every blob of every actor. WebGPU, per frame: deform compute (bones → world center + covariance), project compute (→ screen center + ellipse axes, writes sort keys and histogram), `DepthSort` prefix + scatter (`sort.ts`, one counting sort over the whole scene), then a lean instanced draw. Projection/shading follow three's `GaussianSplat` (MIT). A still object is one bone.
- The sort must give the same order for the same view: the scatter's threads race within a depth bin, so `DepthSort`'s settle pass orders each small bin by index, and `setView` keeps bins a fixed width anchored in depth. Break either and hard edges flicker in pixel mode (verify draws one moment twice and compares). `{ sort: 'radix' }` swaps in `RadixSort` (`radix.ts`: 24-bit keys, three stable 8-bit passes, ties in index order by construction; `radixOrder` is its CPU twin and the WebGL path, tested). Opt in (about 10 ms more at 500k on Matt's phone): the lab's `?sort=radix`, and an Exact sort switch on Diorama (Finish tab, `CreatureStage.setSort`, which rebuilds the world keeping the moment) and Dungeon Run (View tab; rebuilds the hall); both also take `?sort=radix`.
- WebGL has no compute: the vertex shader runs `deformBlob` + `projectSplat` per corner (like a skinned mesh), and the CPU only moves centers (`skinCenters`) and sorts. Both backends share those TSL helpers, so change them once.
- Quads shrink with opacity (`placeQuad`): a blob's quad reaches only as far as it stays above 1/255.
- `rig.ts` `skinBlob` is the CPU twin of the deform pass (used by `checkAgainstCPU`; `skinCenters` is its fast center-only twin, tested against it); change one, change both. Weights go to the GPU as bytes summing to 255 (`packWeights`) and the CPU twin reads the same bytes.
- A compute stage may bind only 8 storage buffers on many phones: joints+weights share one buffer for that reason.
- Skin that stretches (Matt saw the dragon's wings and the frog's legs tear, 2026-11-18; three causes, none an illusion to cover them): (1) blobs only ever turned with their bones, so skin pulled out between two bones opened gaps. `stretch.ts` `weightGradients` (pure, tested) finds, for each blob on two bones or more, how its weights change across the skin from the blobs next to it (same part when `partOf` is known), and `skinBlob` and `deformBlob` add Σ (bone k's place for the center − the blend's) ⊗ ∇wₖ to the blob's axes, capped at `MAX_STRETCH`: change both. A world builds them for every actor by itself (kept per skin); the nine floats ride as bits behind the two skin words in the same buffer (`skinStride`), and a world where nothing is on two bones keeps the two words. (2) `setWeights` cut a fifth bone off as it stood, so skin shared between many bones tore along every line where the fourth and fifth changed places: the four now each give up the fifth's weight first. (3) the cutter's `trueShell` took the middle of a thin sheet for deep (the distance hardly changes there) and left rows of holes at rest: it only corrects a distance that changes faster than one for one. A sculpted part with `span` (the dragon's wing skin) is shared out by 1/distance² so it is held fast at its bones. The sandbox's creatures are posed by `poseBlobs` for Spark and do not stretch yet.

## Brush and Ink (`/experiments/brush-and-ink/`, `src/blobscape/BrushInk.tsx`, `src/splat-core/marks.ts`; issue #235)
- Marks: `SplatWorld.setMarks(look)` / `Stage.setMarks` (kept across actors) draws every blob as a brush mark or ink stroke instead of a soft dot, in the splat fragment (`markOf` in engine.ts) on both backends. A mark is a function of the pixel's place on its own blob (σ units along the screen ellipse's long and short axes) and the blob's seed (`splatSeed`, the `lodRank` hash) and of nothing on the screen, so marks turn with the view and never swim. `markAt` in `splat-core/marks.ts` (pure, tested) is the CPU twin: change one, change both. The ellipse's axes can flip sign frame to frame, so every mark must look the same after a half turn (hatching uses `|v|`; a test holds it). Gouache and oil are opaque paint, set apart on purpose (Matt found them almost identical, 2026-11-21; `DAB`, `GOUACHE`, `OIL` in marks.ts): gouache is short square dabs, matte and nearly flat, a little chalk in every color, breaking up toward their ends as a dry brush does; oil is long narrow strokes with deep ridges lit along their crests, a bead at the stroke's edges, color richer than the blob's own and leaning warm or cool by the stroke; ink and wash is a pale wash with a pen stroke along each blob; hatching draws more lines where the color is darker. Stipple (an idea from Silicon Jungle's Ink Studio) is pen dots on paper, on a grid on each blob, nudged and kept by a hash of the grid place (both unchanged by a half turn), more and bigger where darker (`stippleAt`). Ink and paper colors are part of the look, and the page puts the paper color behind the canvas (`brushLooks.ts`: `LOOKS`, `PAPERS`, `GROUND`).
- Marks are drawn by depth, not by paint order (Matt saw the stripes on the windmill's sails jump as each came round, 2026-11-18): sorted far to near by their centers, the blobs of one flat thing on a grid all change places at the same moment as it turns in the view, and opaque marks show it. So while marks are on the material writes depth, a mark is all there or not (`MARK_CUT`), and `placeQuad` puts each corner at the blob's own depth there (`tilt` from `projectSplat`, kept in the `splatC` buffer on WebGPU; `depthSlope` in marks.ts is the CPU twin, change both) plus a lift by the blob's seed (`MARK_LIFT`), so blobs in one plane tie and the seed says which is on top. The project pass and the draw (with clean cuts) now each bind 8 storage buffers, the most a phone allows. `MarkLook.soft` keeps the old far-to-near laying with soft edges: a scan's thick, overlapping blobs shred into patches by depth, so the scanned mug and Scan Studio use it.
- Outlines (Matt asked, 2026-11-18: an ink drawing with no contours made no sense): `Stage.setOutline(pen)` draws through `splat-engine/inkLines.ts` `InkLines` when not in pixel mode. The frame is drawn three times with one sort (picture, `SplatDepth`, the map of parts) and one pass inks a pixel a pen's width from where the picture's own cover ends, something is clearly nearer (`LINE_DEPTH`), or a lower-numbered part meets another at the same depth (thinner, `LINE_PART`). Weight is `lineWeight` in marks.ts (the CPU twin of `lineWeightNode`; change both): heavier round dark things, swelling along the line, lifting off round light ones; the line wobbles by smooth noise over the screen, so it is the one thing here that does not turn with the view. Ink and wash is a pale wash (`WASH_LEAST` to `WASH_MOST` by darkness) with pen strokes only in shade (`SHADE_FROM`), since the outlines now do the drawing. On for ink and hatching by default (`?outline=0|1`), offered for every look; Scan Studio turns them on with its two pen looks.
- ASCII (the page's `ascii` look, `Stage.setGlyphs(look)`; Matt asked for it after seeing an ASCII-textured game, 2026-11-19; our own method): not a mark. Characters only read upright in rows, so it is a grid of 6 × 8 font-pixel cells fixed on the screen, each font pixel a whole number of device pixels. `splat-engine/glyphPass.ts` `GlyphPass` draws the frame three times with one sort (picture, `SplatDepth`, the map of parts), then a pass a cell a pixel decides each cell (kept beside the frame before's) and one draws the characters from a font strip. `splat-core/glyphs.ts` (pure, tested) is the CPU twin (change both): a cell's tone (`toneOf`: cover times the root of its luminance, or of its darkness on a `light` ground) picks the `RAMP` character whose share of ink is nearest (`rampFor`), unless an edge runs through it (two rings of eight probes; two probes are `across` an edge by cover, depth, part or tone), which gets `|`, `_`, `/` or `\` (`strokeFor`). Steadiness: a cell keeps its ramp character unless another is `steady` closer, a stroke starts only where both rings find it and holds while either does (`strokeHeld`); under a turn too small to move anything a cell, that took changing characters from 1.9% to 0.5% on the windmill. Its own colors are lifted to full strength but at most `LIFT_MOST` times (dark stockings came out pink). `Stage.glyphText()` reads the grid back as text (the page's Copy as text). Off screen the page passes `steady: 0` so a frame doesn't depend on the last (`?steady=` overrides). Outlines and the lens wait while it is on. Strands (`GlyphLook.strands`, Matt's go 2026-11-18 after the first pass): a fourth draw, `SplatWorld.lieMap` (flat mode 4: every blob a hard disc colored by which way its long screen axis runs, as twice the angle, and how long and thin it is there, 0 under `LIE_FROM`; `lieOf` in engine.ts, CPU twin `lieColor`), and a cell whose mean lie is `STRAND` strong takes the stroke nearest that way (`strandFor`, held down to `STRAND_HOLD` and within `STRAND_KEEP`), lit by its tone, before any edge is looked for. A disc on a surface seen nearly edge on is long and thin too, so the rims of round things get strokes along them. The page's Fox in the grass subject is Diorama's `meadow`. Braille and blocks (`GlyphLook.set`, the page's Characters choice, `?chars=`; ideas from Silicon Jungle's Ink Studio): a braille cell's eight dots each come on where its eighth of the cell reaches its `DOT_STEP` (an ordered-dither order; a dot that was on holds `steady` lower), a blocks cell is the quarter block of the quarters over the middle of its tones, or one of ░ ▒ ▓ (dither patterns) where its quarters are within `BLOCK_SPLIT`; `brailleFor`, `blockFor`, `shapeCell` and `setBit` are the CPU twins of the pass's decide and draw (change both). Neither uses edges or strands, and `glyphText` writes their own characters. Not yet seen on a phone or in motion on a real screen.
- Cel shading (the page's `cel` look, `Stage.setCel(look)` on a stage made with `lights`; Matt asked for the illustration looks to come closer to cel shading, 2026-11-19): the light is worked out, not painted on the picture. Every blob is drawn flat in its own color (the `flat` mark, `FLAT_CUT`), and `splat-engine/celPass.ts` `CelPass` draws the frame as picture, map of parts, map of tones and depth, plus the scene's depth as the light sees it (`shadowView` in `splat-core/cel.ts`: a narrow view from `SHADOW_FAR` sizes away round the posed bones' box, `SplatWorld.posedBox()`, snapped onto steps so shadows keep their pixels; 2048², depths sloped across each disc by `depthSloped`). A blob's tone is how it faces the first light, with the side the camera sees taken as its outside, and how sure that is (`toned` in engine.ts, `toneAt` and `flatness` in light.ts: change both; a scene's discs are nearly as thick as wide, so flatness is from the covariance's eigenvalues). WebGPU packs it beside the color in the light buffer (`TONE_SHARE`), WebGL works it out per corner. A light pass puts each pixel back in the world from its depth and asks the light's map with nine taps and a variance test (shaded only when hidden by more than the roughness there, or fur shades itself into dirt); where a blob is not flat the facing comes from the form's own slope on screen. The last pass smooths the light over the surface it lies on (`CelLook.smooth`), cuts it (`celTones`: `CEL_TURN`, `CEL_CAST`, `CEL_BRIGHT`; `celColor`; the CPU twin, change both) and draws an even outline. The engine's 64³ shadow grid was tried first and is too coarse for a clean shadow edge. The page cuts its subjects again with no baked light for this look (`unlit` in voxel.ts) and gathers each part's colors into a few flat ones with `gatherColors` (k-means in OKLab per part, colors within `SAME_COLOR` joined, then a vote among neighbors so speckle goes and stripes stay), shown through `stage.tint`. The light's turn is measured from the subject's starting view. `celLooks.ts` holds the chip, backdrops and defaults. My choices, not Matt's yet: the control names (Light from, Light height, Tones, Cast shadows, Shadow shapes, Colors in each part, Backdrop), the violet shade color, the Sky backdrop, two tones and three fills by default. The scene's own light (Matt saw the lighthouse lose its night and its turning beam in this look, 2026-11-19): the stage's lights stay on as lamps after the look's own (`Stage.light`), `toned` puts how much they reach each blob in the tone's spare channel (`toneAt`'s `lamps`, by brightness, distance, facing and baked lamp shadow, at most `LAMP_MOST`; 1 for a blob that glows), and the last pass adds `lampTint` of the lights as one more tone from `CEL_LAMP`, multiplies both tones by the stage's ambient times `CelLook.ambient`, and leaves what glows its own color (`celColor`'s `by`, the twin). On Diorama a scene with a sky gets a Scene's sky backdrop first (`celLooks.ts` `nightOf`, `nightLight`: under a dark sky both tones are dimmed to `MOONLIGHT`, so lamps and lit windows stand out); gouache and oil stand in front of that sky too. Lamp shadows are the baked ones only, and a sky that turns as a scene plays is not followed. Scan Studio does not offer it (a scan's light is baked in). Not in pixel mode; glyphs come first if both are set. Not yet timed on a phone.
- Neon (the page's `neon` look, `Stage.setNeon(look)`; Matt's idea, 2026-11-19: strands of glowing light that move and light up a scene, bodies darker but catching the light as it moves within the outlines): `splat-engine/neonPass.ts` `NeonPass` draws the frame as outlines do (picture in flat marks with the stage's lights put by, `SplatDepth`, the map of parts, one sort) and one pass finds the tubes where `InkLines` would find lines (the picture's edge, something clearly nearer, a lower-numbered part beside another), even and with no wobble. The light is spread on the screen, so it reaches a body beside a tube in the picture whether or not it is beside it in the world, and bodies behind it too. - Stained glass (the page's `glass` look, `Stage.setGlass(look)`; Matt picked it second of three, 2026-11-19): `splat-engine/glassPass.ts` `GlassPass` draws the frame as outlines do (flat marks with the stage's lights put by, `SplatDepth`, the map of parts), puts each pixel back in the world from its depth and asks which pane it is in: panes are the cells nearest a jittered grid of points fixed in the world (`paneOf`, a 3D Voronoi over the 27 cells round the point, sized as a share of `posedBox`), so they stay on their surfaces as the view turns. - Watercolor (the page's `watercolor` look, `Stage.setWash(look)`; Matt picked it third of three, 2026-11-19): `splat-engine/washPass.ts` `WashPass` draws the picture in flat marks under the stage's own lights (baked light kept: it is the painting's light and shade), softens it at half and at a quarter of its size, and one pass paints the paper, which covers the canvas. ## Sand, Snow and Goo (`/experiments/sand-snow-goo/`, `src/blobscape/SandSnowGoo.tsx`, `src/blobscape/flow/`, `src/splat-engine/mpm.ts`, `src/splat-engine/solids.ts`; issue #162, reworked 2026-11-18)
- Matt's rework: one material at a time and a test, or All three as three lanes; never two materials in one box (on a shared grid they stick as one). The page opens on what its first tab shows (sand, pouring onto a block). Tabs Material, Test, View (my names, not Matt's yet).
- `mpm.ts` (pure, tested) is a 3D MLS-MPM on the CPU: a [0, 1] box on a `cells`³ grid, quadratic B-splines, APIC, `dt` of `STEP_PER_CELL / cells` (3 ms at 24: stiffness, cell size and `dt` are tied, so a stiffer material or a finer grid needs a shorter step). All three are Hencky elasticity with their own way of giving, set by `Mpm.set(knobs)` (`Knobs`, two settings each). Sand: Drucker-Prager (`friction`; `slopeOf` measures the heap), its cone moved into pulling by `damp`. Snow: the same cone with a hold (`stick`) times each particle's bond (`Jp`), which weakens wherever it gives down to `SNOW_CRUMB` (that is what makes clumps; without the crumb share a column either stood whole or fell whole), and a cap on squeezing that rises as it packs (`packed`, `pack`). Goo: volume is elastic and never swells (a swelling stream blew up), shape past `hold`'s yield drains at `thick`'s rate. The first goo clamped every singular value, so it lost 85% of its volume instead of flowing: keep the volume test. Each particle keeps the stress from its last decomposition (`tau`), so a step needs one `svd3` (unrolled; it is a third of the time). Particles stay where all 27 nodes are on the grid, so the loops need no bounds checks. `floorGrip` is the floor's friction (goo's is low, or a thin puddle can't spread on a grid this coarse).
- `solids.ts` (pure, tested, in the package): a `Solid` is a voxel.ts `Shape`, fixed (block, steps, bowl) or a rigid body with weight (`density`). On the grid (`Mpm.meet`) material moving into a fixed solid stops and rubs; a body and the grid points moving into it come away at one speed along the way out, solved for all of them at once (a 6×6, `solve6`), because an explicit kick shook a light body under a heavy heap; the sideways rub is shared by weight for the same reason. A particle the grid let in is put back on the surface and stopped (a lone particle is too few points to be stopped by the grid, and kept speeding up), and a body is kicked back by as much. A body meets the floor, walls and fixed solids on points of its own surface (`corners` for a cube; a ball passes `round` and uses the exact point, or it rocks on its points). It sleeps when still and wakes every `NAP` to see whether what held it has gone.
- `flow/box.ts` (pure, tested) is one box: `Setup` (material, test, ground, thing, size, weight, detail), the spout (a layer each time the stream has fallen a particle's spacing, until one `SPOUT.amount`), the pile and the thing let go after `DROP.after`, the round column, the grounds' shapes, `DETAILS` (cells and capacity per detail) and `frame()`: positions, a `shade` per particle (the grid's mass thins toward the surface, so its gradient is the way out, lit by the same sun as voxel.ts) and `tone` (snow's packing, drawn darker so a print shows). `flow/flow.worker.ts` runs one box as close to real time as the device allows and posts frames ~30 times a second, each with the `id` of its `start` so the page drops a late frame of the last box; All three is three workers.
- `flow/view.ts` builds one actor in the simulation's units (root bone scaled by `SIZE`): per lane a bone with the ground and tray rim cut by `buildVoxels`, a bone each for ball, cube and rock built at `THING_BUILT` and scaled by bone size (the two not falling are size 0), then `capacity` particle blobs a lane on the root (hidden ones clear and tiny, so the count never changes); the page `refresh`es each new frame, as Shape Shifter does. Changing anything on the Test tab, the material or the detail starts the box again; the Material tab's sliders act on the running box. A short tap pokes (`CreatureStage.rayAt`, the nearest particle along the ray in any lane, else that lane's floor). Under reduced motion each box is run 5 s at once and shown paused. Verify drives `window.__flow` with `?offscreen=1` (`?material=&test=&ground=&thing=&detail=`): `pause`, then `run(seconds)` for a set time, `lanes()` and `thing()`.

## Diorama (`/experiments/diorama/`, `src/blobscape/PixelDiorama.tsx`, `src/blobscape/diorama/scene.ts`)
- Renamed from Pixel Diorama (Matt, 2026-11-21): the old address `/experiments/pixel-diorama/` redirects here (vercel.json, and `routes.ts` reads it too); code names (`PixelDiorama.tsx`, `diorama` route, cover and share files) kept the old name.
- Pixel-art scenes from splats, in three parts. `splat-engine/voxel.ts` (pure, tested) cuts shapes given as distance functions into one grid shared by every part; each surface cell is one solid disc lying on the surface, on one bone, with sun, ambient and cast shadows baked into its color. Lit colors stop at `LIT_MAX`; only `glow` parts go brighter, and pixel mode's `GLOW_FROM` sits just above it, so a lamp glows and a white wall doesn't. Keep the two in step.
- Pixel mode is `CreatureStage.setPixels(look, size)`: `splat-engine/pixelPass.ts` draws the scene small into a target, then one full-screen pass does alpha cut, glow, edge lines inside the scene (`edges`: the darker side of an OKLab jump over `EDGE_JUMP`), OKLab palette + Bayer dither, a silhouette outline and an optional `sky` (a top-to-bottom gradient on empty pixels, dithered into the palette; leave it out for sprites; its optional third value, a scene's `skyReach`, is how far down the blend runs before it is all the bottom color), scaled up by a whole number of device pixels. `pixelArt` in `splat-core/pixel.ts` is its CPU twin (change one, change both; verify compares them on WebGPU and WebGL). `stage.pixelFrames()` reads the small frame and the art back. The pass always draws into its `art` target (kept in sRGB, so palette colors are stored exactly) and the screen gets a plain scaled copy. It keeps the art of the frame before as well: a look with `steady` (the page's Steady pixels switch, `STEADY`) lets a scene pixel keep its palette color unless another is clearly closer, which stops pixels between two colors flipping as lights flicker and the view swings. Only a pixel that is scene now can stick: sky and glow-only pixels never do (a pixel the scene has left would keep its color), and it keeps only one of the two palette colors it lies between and never the color the sky would take there (the windmill's sails kept the sky's blue where they had just turned over it, 2026-11-20). `?steady=0` starts with it off. `CreatureStage.step` (the page's Motion choice: Smooth, 12 or 8 a second) holds frames: the pose only moves on every `step` seconds and nothing is drawn in between, which is what stops edges crawling while a view swings; `stage.time` is the held time. `pixelArt(f, look, before)` does the same given `pixelFrames().before`. Lines between parts (`PixelLook.parts`, with or without `edges`): the pass draws the blobs a second time into `ids` as a map of parts (`SplatWorld.parts`: every blob a hard disc in its part's flat color, from `Actor.partOf`, reusing the frame's sort), and a pixel beside another part whose color is too close for a color line takes a line when its part is the lower-numbered (by number, not lightness, so the line keeps its side as lights flicker). `pixelArt`'s fourth argument is that map (`pixelFrames().parts`). Lone-pixel cleanup (`PixelLook.tidy`, the page's Clean up lone pixels switch, on by default, `?tidy=0` starts it off; issue #114): a second pass over the art (`tidied`; `art` is that target when on, while `before` stays the uncleaned art, which is what steady pixels compare against) gives a scene pixel the color six or more of its eight neighbors share when none shares its own; with a map of parts, only a pixel among four or more of its own part, so specks and eyes stay. `tidyLone` is its CPU twin, which `pixelArt` runs last. Calmer pixels (`PixelLook.calm`, the Finish tab's switch, on by default, `?calm=0`; after Silicon Jungle's Ink Studio cleanup pass, 2026-11-20: Matt found our pixel art less clean than theirs) takes the tidy pass's place: a scene pixel takes a color five (`CALM_MOST`) or more of its eight neighbors of its own part share, and `calmEdge` finds one-pixel bumps and notches on a silhouette (a bump stands out from a wall, a notch from open backdrop, so stars, line tips and one-pixel gaps stay) and fills or clears them, the outline following. It also cleans lines on the scene and its outline (`lineFix`, after Ink Studio's line cleaner: a one-pixel kink in a straight edge between two colors goes, and the doubled pixel at the inside corner of a dark line, so lines meet corner to corner), never on the sky. `calmArt` is the CPU twin of the pass's calm branch (change both). Flat surfaces (`PixelLook.flat`, `?flat=0`): a scene pixel gets no dither unless a glow spills onto it, while the sky keeps it, as a pixel artist dithers. With it on, the map of dither steps (`surface`) is not drawn, since only a glow's spill is dithered and the map cost a whole draw of every blob (Matt found the dragon slow on his phone, 2026-11-20). A pixel a glow lights snaps only to a palette color of its own hue, the light's or a gray (`keptNearest`, `HALO_HUE`, `HALO_GRAY`; twin in the pass's palette loop), because a lamp's yellow over gray stone snapped to olive greens and browns (Matt saw ragged rings round the lighthouse windows, 2026-11-20). Matt asked (2026-11-20) for fewer Finish options: the tab shows Dither, Glow, Paint in steps, Outline (chips: None, One color, Each thing's own), Lines inside the scene (edges and parts together), Sky behind, Heat haze, Color cycling (scenes with one) and Rock the view; the rest are always on and only the address turns them off. Verify sets the art-pixel effects and the exact sort through `window.__diorama.finish`. Specks (`calmArt`'s speck step, after Ink Studio's): a patch of one or two pixels on a part takes the color `SPECK_MOST` of its neighbors there share, unless it is `SPECK_KEEP` lighter or darker (a highlight, an eye); the mode filter leaves such pixels alone too. Deliberate light (`PixelLook.rim`, `shine`; `?rim=0`, `?shine=0`): a scene pixel whose neighbor toward the sun (`Diorama.sun`, turned across the picture from the scene's starting view by `screenWay`, `rimStep`) is backdrop, and the peak of a smooth lit form (`peakAt`), take the palette color a step lighter in their own hue (`lighterStep`); twins in the pass, which counts rows up, so the rim's y turns over. Shade each pixel (the Finish tab's switch, off by default, `?shade=1`; Matt picked per-pixel shading next, 2026-11-20): the scene is cut unlit, each part's colors gathered into `PIXEL_FILLS` flat ones, and the pixel pass's small picture is drawn by `CelPass` (`PixelPass.drawScene`, set by the stage whenever cel shading is on in pixel mode: `celInPixels`, no line, at the small picture's size) lit by the scene's own sun (`Diorama.sun`) in two tones, shade at the description's ambient share (`Diorama.shade`, `shadedLight`) and everything held under `LIT_MAX` so only glowing things reach the pass's glow. ## Scan Studio (`/experiments/scan-studio/`, `src/blobscape/ScanStudio.tsx`, `src/blobscape/scan/`)
- Opens a phone splat scan (.ply/.spz/... via `readSplatFile`, capped at 800k blobs, 300k on phones), or a made-up sample mug (`scan/sample.ts`, with floaters and haze, tipped off level).

- Colliders (issue #238; `splat-engine/colliders.ts`, pure and tested, in the package): a `Collider` is a box, ball or upright cylinder turned only about the upright. `groundOf` is the `Ground` `plantFeet` takes (`groundBelow` leaves out tops too high to step onto), `pushOut` keeps a point out, `pickCollider` finds one by a ray, `handlesOf`/`resized` are the size handles, `wireOf` its lines for drawing, `guessColliders` the table slab and a box round the kept blobs, and `writeColliderGlb`/`readColliderGlb` a .glb of ordinary nodes with a mesh each (`extras.blobscape_collider` is what we read back; `KHR_implicit_shapes` and `KHR_physics_rigid_bodies` are written as used, not required).
